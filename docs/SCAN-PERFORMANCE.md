# 扫描耗时排查与按需重复检测

## 已确认原因与未确认部分

源码默认`ScanForDuplicates=false`，但此前会读取INI并在扫描目标选择框沿用上次勾选。重复检测在目录遍历工作线程内执行，按文件大小、4KiB、1MiB及完整内容逐级筛选；相同大小、前缀相同的候选可能读取整个文件。它与空间扫描交织，关闭结果页并不会停止已启用的哈希工作。

上一轮本机GUI验收目录的独立INI保留`UseFastScanEngine=0`、`ScanForDuplicates=1`，用于覆盖普通扫描及重复展示。如果继续从该目录启动，旧版会沿用这些测试配置；公开Artifact当时不包含这个测试INI。不能据此确认用户每次真实扫描都使用同一配置。

快速扫描的默认开关为true，但仅整卷驱动器目标尝试读取NTFS的MFT；普通目录目标不走该路径。卷句柄、NTFS信息或MFT读取失败会静默回退普通枚举。管理员权限通常影响能否读取MFT，勾选快速扫描不保证实际使用；本轮不自动提权、不改变权限或回退逻辑。

普通扫描已使用批量目录读取，仍有逐目录句柄、特殊文件物理占用查询、重解析点分类等元数据成本。整卷枚举结束后还会进行硬链接占用修正、排序及扩展名统计。为保证准确性，本轮均保留。没有证据说明树图显隐导致十几至二十分钟耗时，也不修改该功能。

本轮未扫描真实C盘，缺少真实盘各阶段计时、实际后端、文件数量和磁盘负载记录，所以不能认定唯一瓶颈或承诺全盘提速比例。

## 实际修改

- 普通启动忽略历史重复检测开关，仅显式`/SaveDupesTo`直接启用；`/SaveTo`及其他普通启动不执行重复哈希。
- 每次打开扫描目标选择框均默认不勾选重复检测；仅确定后应用本次选择，取消不改变当前扫描模式。明确提示会读取内容并增加耗时。
- 手动勾选仍使用原完整检测算法及当前用户哈希设置。刷新当前结果保留本次模式，选择新目标需再次勾选；不强制改变用户的采样选项，新配置仍默认全量哈希。
- 状态栏展示空间扫描、含重复检测的空间扫描、硬链接修正、统计整理，以及完成、已停止或不完整。耗时为含暂停的墙钟时间，计数为根节点已列出文件，不冒充本次刷新处理数量。
- 原标题百分比仍按发现的物理字节估算，不代表文件完成率或剩余时间。阶段信息不承诺严格进度百分比，也不标识实际NTFS后端。
- 发布包加入干净`WinDirStat.ini`，不带测试扫描路径、结果或测试模式，自动提权关闭、快速扫描开关开启、采样哈希关闭。旧INI不自动覆盖。

## 验证设计

- 已在旧版`b7c34f8`构建产物上复现：合成目录、旧INI开启重复检测，普通启动出现重复页，新增策略测试在第一条行为断言失败；没有访问真实磁盘内容或删除文件。
- 云端仅运行指定`scan.policy`与`scan.workloads`场景，并用`KeepArtifacts`保留测试文件，不执行删除场景。前者验证普通启动、显式检测、取消和新扫描策略及空间报告一致；后者使用64个2MiB合成文件，共128MiB，前1MiB相同、后部不同且仅两个真副本，比较普通枚举与完整重复检测工作负载。
- 小规模双语合成扫描继续运行。所有场景核对原文件哈希不变；仅上传无路径、无所有者字段的检查摘要和耗时，原始报告留在Runner临时目录。
- 工作负载计时包含程序启动及报告导出，受文件缓存、Runner负载及运行顺序影响。它用于说明工作量差异，不代表本机全盘加速比例。

云端编译、策略回归及工作负载对照结果待本轮执行后补记。

## 本机后续验收

在新便携目录先用合成数据验收普通扫描和本次勾选重复检测。真正需要整盘对照时，由用户自行使用相同范围与过滤条件，分别记录是否勾选重复检测、是否管理员运行、目标为整卷还是目录、各阶段停留时间及文件数。普通权限下不可访问的目录仍受系统限制；不要把权限差异当成速度优化或统计范围完全一致。

尚未覆盖隔离NTFS虚拟盘MFT成功及各回退原因、真实盘长耗时、全部停止/暂停/错误边界和大规模内存性能。
