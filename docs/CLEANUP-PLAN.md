# 安全清理计划与只读模拟

日期：2026-10-23。正式功能仅实现计划和模拟，没有真实清理后端、删除按钮、提权或权限修改。独立测试程序的受控回收实验见文末，不进入主程序。原扫描、重复检测、缓存识别规则及原WinDirStat删除入口保持原状；新增保护只适用于本计划流程。

## 计划边界

从完整、无失败且未截断的预览中复制勾选候选，生成独立ID、规则及配置快照。排序、隐藏空文件不会改变已有选择，未勾选及扫描后新出现的文件不加入计划。父预览在计划模态窗口打开期间不可编辑，切换处置方式生成新计划，不修改旧计划。取消或不完整预览不能建立可用计划。

计划逐项保留规范路径、卷号、文件ID、逻辑大小、分配大小、创建和修改时间、NTFS变更时间、规则ID及版本、原因、风险、再生评估和明确处置方式。建立时已变化或无法读取的条目留在计划中，显示跳过原因；不自动修正为新对象。

| 处置意图 | 本阶段行为 | 预计释放 |
| --- | --- | --- |
| 回收站，默认 | 只核验文件条件，不调用Shell；未验证位置可回收性 | 0，同卷回收不算释放 |
| 永久删除 | 仅显式选择后的模拟，不执行删除 | 通过复核项的分配大小上限 |
| Windows官方清理 | 明确跳过，不支持的处置方式 | 0，不切换为文件删除 |

上述数字不是实际释放，模拟的实际释放字节始终为0。没有自动降级、自动重试、计划重放或删除扫描后新文件的能力。

## 模拟复核

1. 比较计划与当前锚点、启用类别、排除项、保护目录、候选上限，以及完整内置规则定义；配置变化即逐项跳过，要求重新预览。
2. 复用原只读扫描器重新判断精确规则路径、年龄、排除、保护、祖先链接、文件属性、硬链接及命名流资格，不复制或改写识别规则。
3. 逐项以GENERIC_READ重新打开，但不读取载荷；FILE_SHARE_READ拒绝普通数据写入及删除访问的共享冲突。仅申请FILE_READ_ATTRIBUTES会绕过共享检查，不能用作占用复核。同一个只读句柄保留到本次元数据判定完成，比较卷及文件ID，前后复读最终路径、大小、创建/修改/变更时间、属性、链接数和删除状态，并检查祖先。访问时间不作为内容变化依据。共享冲突、无法读取和路径异常均跳过，保留系统错误码。
4. 新扫描未能完整核验且目标不在合格候选中时记为复核失败，不能当作安全。能够独立核验的其他条目继续；取消后剩余项逐项标为取消，已取消计划换一个令牌也不能恢复为可用。每项开始时再次核对配置，一旦变化，本轮剩余项持续跳过，即便配置随后被改回。

结果仅保留内存。SimulationResult关联计划ID、模拟标志、起止时间、预计上限与实际0；每项OperationRecord包含计划内索引、起止时间、状态、稳定原因码、系统错误码与估计值。索引可解析回不可变计划中的候选、规则和处置方式，为后续日志及失败处理保留关联结构。本阶段没有持久化操作日志，也没有真实执行成功状态；后续必须另行实现日志写入失败阻断、崩溃未知态及真实处置结果。

逐项结果回调在该项记录完成后触发，不传递文件句柄，不是执行入口；异常会停止本次调用且不自动重试，不提供持久化日志保证。正常返回时，所有计划项各有一条结果，跳过或取消的估计为0，汇总等于逐项估计之和，实际释放始终为0。读取失败在模拟中记为带原因和系统错误的跳过，不表示发生过真实处置失败。调用方须在同一线程内协调配置变更，不支持无同步地从另一个线程修改ScanOptions。

## 观察窗口与真实执行门槛

| 窗口 | 当前保护 | 仍未解决 |
| --- | --- | --- |
| 预览后、建计划前 | 再开文件并比较卷/文件ID、大小和时间 | 预览不持有对象，不能将旧路径直接用于处置 |
| 新鲜资格扫描后、逐项复核前 | 新文件不入计划；再次核身份、元数据、祖先和配置 | 资格与元数据不是同一原子快照；目录中新建仓库标记等保护语义仍可能变化 |
| 只读句柄持有期间 | 拒绝普通数据写/删除共享冲突；同句柄双读，身份不会被回收复用 | FILE_WRITE_ATTRIBUTES专用句柄不在普通数据写共享保证内；父目录未逐组件绑定，双读也不是文件系统事务 |
| 句柄关闭、结果发布及之后 | 只发布模拟观察，不返回可执行句柄 | 名称、父目录、权限、规则状态都可再次变化，模拟结果立即可能过时 |
| 权限变化 | 当前读取权限不足返回访问拒绝，不提权、不改ACL | 能读取不代表有DELETE、父目录删除子项或Shell处置权限；已有句柄权限也不能代表后续重新打开时的权限 |

本机合成映射探针中，普通可写映射在原文件句柄关闭后仍令GENERIC_READ/FILE_SHARE_READ打开返回错误32；映射改写的字节变化却未反映在同时读取的创建/修改/变更时间中。前者只证明这一构造被拒绝，后者说明不能把元数据等同于内容证明。不同映射、驱动、特权进程和时间戳恢复情形未全面验证，不宣称此共享方式覆盖全部内容变化。

进入真实执行开发前必须另行验证：

- 永久处置必须绑定同一个经过核验且具备必要访问权的文件句柄，核对卷和文件ID，持有到操作及逐项结果确定；不能关闭后按同名路径重新打开。祖先目录也需使用目录身份、句柄绑定或等效平台机制验证完整解析过程，防止越界和重解析点替换，无法证明时跳过。当前没有这种执行句柄或后端。
- 回收站和Windows官方维护接口的目标绑定、权限、失败及取消语义须分别在隔离环境验收；若接口不能保证计划对象不被替换，只能保持不支持，不能借用永久删除或批量清空。内容一致性、应用退出及缓存配对语义也须独立验证。
- 固定规则/排除版本，并在实际操作提交点复核保护与权限；持久化开始和逐项日志，日志失败阻止后续项，崩溃未知结果不重放。真实处置仍须单独授权，本轮不实现或调用。

## 隔离回收实验（正式执行阻断）

用户另行授权仅测试程序自建合成数据的真实回收。新增tests/RecycleBinPrototype及其独立测试目标，不链接主程序，也不提供外部路径参数。每个实例在临时目录下创建随机全新根，以CREATE_NEW创建文件，从原创建句柄取得卷及文件ID，用ReOpenFile建立持续持有的对象凭据；只扫描该实例的锚点。其他实例或任意计划不能授予文件所有权。样本不自动删除，不枚举或清空已有回收站。

计划后端Evaluate复用既有计划复核，合格项也返回BindingUnavailable，readyForRealFiles恒为false，不调用Shell。独立ShellControl仅作有真实副作用的接口实验，绝不能用于真实用户文件。它从固定本地NTFS卷逐级打开、校验并持有祖先目录句柄，拒绝重解析点及最终路径不一致，拒绝祖先普通写入和删除共享；末级实验句柄明确允许删除共享，以观察Shell行为，不能宣称这已绑定处置对象。固定祖先目录不等于冻结子项名称，仍可将原对象移出，再CREATE_NEW占用原名。

微软[IFileOperation::DeleteItem](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-deleteitem)接收IShellItem，没有已验证HANDLE或expected FILE_ID参数。[IFileSystemBindData2](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-ifilesystembinddata2)中的文件ID属于名称解析优化，未承诺最终处置原子比较。前置回调再次核验身份可以拒绝此前的替换，但回调返回到实际处置仍有竞态；禁止将其接入正式流程，禁止释放更严格的身份守卫后自动重试。

实验显式设置[FOFX_RECYCLEONDELETE](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)，无提权标志、永久删除、Shell失败回退或自动重试。每次只入队一个自有普通文件，禁止关联元素及复制钩子。逐项记录入队、PerformOperations、GetAnyOperationsAborted、前后回调、真实hrDelete、新回收站对象及其身份；[PostDeleteItem](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-postdeleteitem)成功却无回收站新项必须记为未知/异常，不能事后视为已阻止永久删除。回收不是释放空间，实际释放仍记0。

新增云端verification=recycle-experiment模式保留既有主程序构建和双语合成扫描，只运行新无界面实验，跳过旧核心及GUI场景，避免重复模拟及旧场景的ACL改动。权限实验使用当前账号受限令牌，不改ACL、不取得所有权。最终源码2d93690的[运行39894584072](https://github.com/moshilan/windirstat-disk-cleaner/actions/runs/39894584072)通过：主程序2分22.12秒、实验15.86秒，均0警告/0错误；45项检查0失败，正常回收后核对原ID、祖先固定及既有重解析拒绝、身份锁错误32、真实权限错误5、两处取消、跨实例拒绝；部分实验为2回收、1失败，统计与逐项结果一致。双语合成扫描输入不变。未重跑原GUI或原模拟全集，最终制品及摘要见BUILD-BASELINE。

确定性反例中，前置回调核验旧对象后，用仍打开的原句柄将其改名至自建retained目录，再CREATE_NEW原名；全部原祖先守卫保持。Shell实际回收的新项精确匹配新receipt而不匹配旧ID，旧对象留在retained。回调前同样替换则被E_ABORT阻断，原对象与替代对象均保留。身份读取失败不能当作反例：既不匹配旧ID也不匹配新ID时记Unknown，停止实验。首轮同目录注入被守卫拒绝而失败的记录保留，未释放守卫或放宽断言来取得通过。

进入正式清理仍缺少有文档保证的原子目标绑定、保护/规则提交点一致性、持久化开始与逐项日志、崩溃未知态及取消后的对账。本实验即使通过也不具备接入正式清理流程的条件。

## 按句柄同卷隔离评估（源绑定通过，目标绑定阻断）

新增独立HandleIsolationTests，不链接正式程序、不接GUI，也不调用Shell、永久删除、ACL修改或提权。每个实验全新创建根目录及文件，身份从CREATE_NEW原句柄和ReOpenFile建立，比较卷号及完整128位文件ID，并持续持有凭据；不接受外部路径。复用现有NormalizeDirectory和标准Runner工具链，不变更扫描或缓存规则。

验证[SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)的FileRenameInfo：源为经核验且具备DELETE访问的同一个句柄，ReplaceIfExists始终FALSE，文件名缓冲显式留NUL尾且长度不含NUL。Rooted实验传目标目录HANDLE和固定单段相对名，不解析任意子路径；[当前结构文档](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info)描述支持这种用法，但本机及标准Runner实测均返回87，源文件及目标保持不变。本次调用组合无法据此建立可执行的目标绑定，不推广为所有Windows版本或接口均不支持。失败绝不回退全路径；本轮未扩展到Native接口。

AbsoluteControl仅为独立新样本的接口对照，不是Rooted的执行器或失败回退。[源码47dc72c的标准Runner运行39897827709](https://github.com/moshilan/windirstat-disk-cleaner/actions/runs/39897827709)通过14个场景、441项检查：源名称替换后同句柄仍移动原对象，新同名文件保持；正常隔离和显式恢复的完整ID与分配大小一致；目标和恢复名称冲突均183且不覆盖；占用32、受限令牌源及目标权限5、已有重解析点阻断、取消1223及恢复父目录更换阻断通过。主程序与实验均0警告/0错误，双语合成扫描输入不变；未重跑旧GUI、模拟全集或Shell回收。

目标反例同样成立：目标末级目录从开始即允许内核创建子项所需共享写，保持目录句柄及全部祖先强守卫，前置检查确认普通目录后将空目标目录设为指向另一自建目录的junction，全路径改名把正确源对象移入该替代目录。按源句柄操作不会误选同名源文件，却不能约束目标路径解析。若末级目标也禁止共享写，改名返回32；独立样本未放松守卫重试。因此两个对照都不能视为已通过安全隔离验收。

观察中断测试在改名成功、结果尚未发布的边界关闭全部文件及目录句柄，重开后比较原父目录与目标父目录身份、两处文件身份，再作显式恢复对照；原父目录被替换则阻断。身份保留在内存，未实现持久化操作日志，也没有实际杀进程、系统崩溃或掉电验证，不能称为完整异常恢复。正式设计仍需操作前刷盘意图、计划/源/两端目录身份及内部目标名、结果与未知态记录；恢复须按身份对账，找不到原对象、目录变化或同名冲突时转人工，不自动重放或覆盖。句柄关闭后的ID复用、内容改写、目录链变化和日志持久性未由本测试消除，不能只凭历史ID自动处置。

同卷改名保留原数据和分配，不会立即释放同卷空间，实验释放统计为0且不等同于实际空闲空间测量。后续释放空间只能在另行授权和日志/身份/内容/权限验证完备后，研究对同一个已核验句柄的最终处置，且需确认最后的链接及句柄释放；本轮不实现。跨卷搬移包含复制与删除，不能用作本轮替代；已证实不绑定身份的Shell回收也不能成为隔离后自动步骤。

无论接口对照是否通过，正式计划继续阻断；源绑定成立不等于目标目录绑定、内容稳定或崩溃恢复已成立。实际验证结果见BUILD-BASELINE。

## 自建合成缓存的句柄删除实验（不接入正式执行）

用户另行授权本轮仅处置程序自行创建的合成文件。tests/HandleDeleteTests沿用既有实验的CREATE_NEW凭据、创建对象派生的保留句柄、完整卷号/128位文件ID、逐组件祖先固定与受限令牌模式，独立编译，不链接主程序，也不接受外部路径。既有Shell入口、扫描/缓存规则、GUI和隔离实验不改。

仅采用官方[SetFileInformationByHandle](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileinformationbyhandle)的FileDispositionInfo，DeleteFile=TRUE。先一次取得GENERIC_READ|DELETE且仅共享READ的句柄，再在同一句柄核对原创身份、最终路径、元数据、单硬链接、默认数据流及祖先身份/非重解析状态；最后一次复核和取消门之后直接设置删除待定，绝不关闭后按名称重开删除。不使用POSIX、忽略只读、清属性、提权、ACL修改、重启删除或失败降级。任一观察到的保护失败均拒绝处置。

实验区分Rejected、Cancelled、MarkedPending、NameAbsent、Unknown。API成功只表示设置待定；保留句柄尚开时不报最终完成，关句柄后观察名称消失也不等于测得空闲空间。普通语义下须最后相关句柄关闭、无剩余链接及文件系统完成回收才可能释放分配；映射、驱动、快照、存储机制及异步回收仍影响时机，不承诺擦除底层数据。本操作不进回收站，提交之后不承诺取消或恢复。统计actualReleasedBytes保持0且spaceMeasured=false。

该实验不构成受限缓存后端的上线验收。依据[CreateFile共享语义](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)，属性/扩展属性访问不受普通共享标志完整约束；末次元数据/链接/流/保护规则观察和提交仍不是原子事务，既有DELETE能力也不自动随之后的ACL变化撤回。实测的文件ID绑定仅解决对象被同名替换的一部分风险。尚未证明应用已停止、载荷未被映射/特权代码改变、缓存确实可再生及配对清理语义；没有持久化提交日志、真实进程崩溃/掉电和未知结果恢复测试，不得自动重放。readyForRealFiles=false，正式执行继续阻断。测试的部分结果仅为2完成+1预检拒绝，不冒充处置API部分失败。
