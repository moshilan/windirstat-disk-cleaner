# 垃圾清理与统一安全实施方案

状态：供下一阶段评审的实施方案，尚未开发或验收。日期：2026-10-21。

基础为WinDirStat提交49d81479c034cd7dd2cc03bd007a1d41d779840f。保留目录占用分析、大文件识别、重复文件检测及现有主布局，新增一个原生垃圾清理窗口。第一版采用本机x64作为首轮验证对象；最低支持系统和额外架构在发布前确定。

## 1．第一版功能边界

| 分类 | 纳入范围 | 排除与处置约束 |
| --- | --- | --- |
| 系统垃圾 | 当前用户临时文件、Windows临时目录中有明确规则的文件；按年龄和占用情况筛选 | Windows临时目录权限不足即跳过；WinSxS、Installer、DriverStore、更新维护目录、Prefetch不靠通配规则清理；不承诺覆盖全部Windows维护能力 |
| 常见软件缓存 | 首批Edge、Chrome、Firefox已确认版本的缓存子目录 | 软件运行时跳过；不清配置、密码、Cookie、历史、书签、扩展、会话和数据库；支持的版本及目录清单随规则交付 |
| 回收站 | 当前用户、明确选择卷的Shell条目枚举、预览及永久处置 | 不递归访问$Recycle.Bin；不触碰其他用户SID；不隐含清空其他卷；需单独不可恢复确认 |
| 开发工具缓存 | 首批pip下载缓存、npm缓存；已核实的可再生IDE缓存后续逐条补充 | 默认未选，提示重新下载、离线使用及重索引影响；源码、.git、虚拟环境、凭证、Docker/WSL磁盘、项目产物和离线依赖库不自动当垃圾 |
| 自定义规则 | 一个明确根目录、文件通配、递归开关、最小年龄、排除项；新增、编辑、禁用 | 默认未选；禁止shell、脚本、注册表及数据库动作；不接受盘根、用户根、系统根和整棵AppData的宽泛规则 |

规则只选择具体文件；第一版不按通配递归删除整个目录树，不自动删除扫描后新出现的文件。空目录移除可以后置。

内置规则的最小年龄初拟7天，自定义规则默认7天；这是保守的产品初值，并非Windows官方安全阈值，需规则样本验证后定稿。回收站年龄单独展示，由用户选择，不隐含沿用该阈值。

首版不引入Python、BleachBit运行时、服务、插件系统、在线规则市场或独立权限进程。保留上游许可；是否使用其他仓库规则另行审核。

## 2．实体与输入输出

| 实体 | 最小字段及生命周期 |
| --- | --- |
| CleanupRule | id、version、category、name、root anchor、relative patterns、recursive、minimum age、excludes、risk、disposition；启用、禁用、编辑；编辑使旧预览失效 |
| ScanSession | session id、规则与排除配置版本、目标、开始结束、警告；待扫描→扫描中→完整预览或取消、失败 |
| Candidate | 来源类型、规则来源、大小、修改时间、风险、操作、跳过原因、勾选；普通文件保存规范路径及卷与文件ID，回收站保存本次枚举的Shell条目标识或对象快照；仅完整且可核验候选可执行，不递归$Recycle.Bin补身份 |
| CleanupPlan | plan id、快照、用户选择、配置版本；待确认→已确认→执行中→完成、取消或部分失败；不自动重试 |
| OperationRecord | 时间、plan id、规则版本、候选、操作、结果、错误码；仅追加，日志目录本身受保护 |
| DuplicateKeepSet | 拟处置组及指定保留成员；执行前重新核验，保留成员失效时该组停止 |

输入链：内置或自定义规则、Known Folder解析、用户卷选择、排除设置、文件元数据、Shell回收站对象、原重复组。

输出链：候选列表及统计→人工选择→计划确认→安全复核→逐项执行→日志与结果→受影响的原空间树刷新。清理扫描不要求先对C盘做完整扫描。

无数据时显示零候选和跳过原因，执行不可用。候选数量较大时分批更新列表，统计与选择不得漏项；数据量限值与性能指标须在真实构建可用后用合成大目录确定。

## 3．统一安全策略

| 机制 | 第一版要求 |
| --- | --- |
| 风险分级 | 低：已验证可再生临时文件；中：重下载或改变使用体验的缓存；高：回收站永久处置、自定义未知范围。受保护对象属于禁止项，不靠再次确认放行 |
| 默认选择 | 首次预览均未勾选；用户主动选低风险可用批量选择，高风险单独确认；不可把类别名称当安全证明 |
| 重要目录 | 禁止系统组件与安装根、个人文档和桌面等数据目录、仓库、密钥和凭证目录；仅经审核的内置规则可处理Windows Temp或AppData内的精确白名单缓存子目录，仍服从全局排除、链接保护和执行前复核；不授予整个系统根、安装根或AppData例外，自定义规则不得取得该例外 |
| 自定义根 | 用已知目录解析与路径规范化后检查；盘根、用户根、系统根、保护目录或其危险祖先均拒绝；数据目录仅允许只读分析，不通过通配规则处置 |
| 排除规则 | 全局排除优先于内置和自定义匹配，扫描与执行均核对；匹配目录边界和Windows路径语义，不以简单字符串前缀代替 |
| 文件身份 | 普通文件记录卷标识及文件ID，执行前重新打开并比较身份、长度、修改状态和规则配置，检查祖先重解析点；回收站重新核对枚举快照中的Shell对象，仅处置对应条目；无法可靠核验即跳过 |
| 链接与云文件 | 不跟随junction、符号链接、挂载点和云占位文件；不能只检查末级文件；身份核验和实际处置间的路径竞态需要专项测试，不能宣称仅比较元数据就完全解决 |
| 文件变化和占用 | 内容、身份或路径变化即跳过；共享冲突与ACL拒绝不强删，不安排重启后删除；规则所需应用进程状态在执行前再检查 |
| 重复文件 | 保留原扫描；采样结果不直接执行。对拟删除成员和保留副本重新做全内容比较、变更与身份检查；同一物理文件的多个硬链接不计为独立可回收副本；必要时检查ADS，不支持则跳过处置 |
| 保留副本 | 不允许全组勾选；每组至少指定一份仍存在的独立副本。通过父目录批量删除也不得间接删掉保留项；原始列表删父目录时有同样保护，或在首版拒绝这类目录处置 |
| 回收与释放空间 | 用户数据优先回收站，失败不自动转永久删除；已验证缓存永久删除须明确告知。移入同卷回收站或隔离目录不记作释放空间；估算与实测空闲变化分别展示 |
| 回收站处置 | 用Shell条目快照只处理已确认对象，新增条目不加入本次计划；当前上游多卷SHEmptyRecycleBin入口在普通模式禁用或改为显式受控流程，不作逐项计划执行器 |
| 权限 | 首版普通用户运行；权限不足展示跳过；不接管所有权、不改ACL、不停服务、不自动提升。若被外部以管理员启动，规则和保护仍生效，并显示权限状态；后续系统级提权单独验收 |
| 日志 | 开始前写计划摘要，逐项追加成功、跳过、失败；日志写失败时停止启动后续操作。崩溃恢复只标明结果未知，不自动重放；不存文件内容或凭证，不采集其他用户数据 |
| 取消和撤销 | 取消仅停止后续项，已完成项不自动回滚；回收站项可在系统中恢复，不承诺程序事务回滚。永久删除与回收站清空不可撤销，必须明确展示 |

并发边界：本进程同一时间只执行一个处置计划，扫描或规则编辑不能悄悄改变已确认计划；原删除操作在清理执行中禁用。其他进程改动由执行前复核处理，不引入后台服务和分布式锁。

## 4．现有入口与改动边界

| 位置 | 下一阶段用途 |
| --- | --- |
| MainFrame.*、WinDirStatModel.h Routes() | 注册清理窗口及安全设置入口，沿用主布局 |
| 新增Cleanup/、Dialogs/CleanupDlg.* | 规则、候选、计划、策略、日志和原生预览窗口；名称为方案，不表示文件已创建 |
| Pages/PageCleanups.* | 现有任意命令模板不混入受限规则；新增受限规则编辑页 |
| Options.*、Filtering.* | 保存安全配置、排除和窗口状态；参考匹配能力，执行策略独立检查 |
| WinDirStatModel.cpp DeletePhysicalItems() | 小范围抽取路径文件操作；加入统一守卫与日志，不重写扫描模型 |
| WinDirStatModel.Actions.cpp | 回收站删除、永久删除、清空文件夹都经策略；原多卷清空和任意命令存在旁路，普通模式须禁用或改为受控流程 |
| MainFrame.Commands.cpp QueryRecycleBin() | 参考统计；新增Shell条目适配，不直接递归回收站目录 |
| Controls/FileDupeControl.*、ItemDupe.*、Item.Extended.cpp | 保留检测和分组，接入准确复核、保留成员和处置结果 |
| windirstat.rc、resource.h、res/langs/、vcxproj | 新窗口、文案和工程登记；不随意改工具集 |

统一保护的保证范围为新清理、原文件删除、清空文件夹、重复文件处置和回收站。原任意COMSPEC自定义命令不受文件计划约束，普通模式必须关闭执行入口；不能在保留这个旁路可执行的同时宣称所有删除均受统一保护。压缩、VHD优化、远程存储等已有非清理功能不在新增安全保证内，需明确入口与范围，不能顺手改写。

## 5．分阶段实施与交付

| 阶段 | 修改范围 | 验收方式 | 预期交付 |
| --- | --- | --- | --- |
| 0．当前基线 | 来源、README、AGENTS、构建记录、方案、Git | SHA及源码一致；可构建时在合成目录运行原程序 | 本轮仓库及文档；构建和运行未通过时明确标阻塞 |
| 1．规则和只读预览 | 新增规则、候选扫描、对话框及资源登记 | 五类范围可解释；年龄、排除、取消；文件哈希不变 | 可预览版本，执行入口不可用 |
| 2．自定义规则和保护 | 新增规则编辑、安全设置及Policy | 危险根、路径边界、祖先链接、全局排除、配置变化用例 | 规则编辑与保护可测试版本，仍不做真实用户删除 |
| 3．缓存执行与日志 | Executor、日志、少量公共文件操作抽取 | 合成数据的确认、复核、锁定、权限失败、部分失败及取消 | 可执行低中风险缓存清理版本 |
| 4．重复与回收站 | 修改原删除入口和重复组处置，新增Shell适配 | 全内容复核、保留副本、父目录旁路、新回收站条目隔离 | 四项核心能力及统一保护齐全的首版候选 |
| 5．回归与交付 | 隔离回归、必要修复、便携打包和说明 | 原有三类能力回归；结果和日志一致；实际支持范围明确 | 便携包、规则清单、验收记录和限制说明 |

每阶段独立本地checkpoint；实现前先评审对应范围，不能把本轮方案当作自动授权进入下一阶段。首次真实用户缓存清理不属于本轮或合成测试授权。

## 6．关键验收标准

以下均为后续验收目标，本轮未执行。所有处置测试仅用合成数据或隔离虚拟磁盘。

| ID | 前置与操作 | 可观测期望 |
| --- | --- | --- |
| AC-01 预览只读 | 准备临时、缓存、自定义样本及哈希，运行预览 | 候选路径、大小、规则、风险和操作可见；文件内容、数量和回收站不变 |
| AC-02 年龄与排除 | 新旧文件、全局排除文件夹、名称前缀相同兄弟目录 | 仅达到阈值且未被排除的文件成为可选候选；兄弟目录不被错误前缀匹配 |
| AC-03 危险规则 | 输入盘根、用户根、受保护根、越界相对路径及脚本命令 | 保存或预览被拒绝并显示原因；无执行路径 |
| AC-04 预览失效 | 预览后编辑规则或排除项 | 原计划失效，要求重新扫描；不沿用旧选择直接执行 |
| AC-05 变化文件 | 预览后替换同名文件、修改内容或替换祖先目录为链接 | 变化或无法核验条目跳过并记录；保护目录无改动 |
| AC-06 运行中应用 | 浏览器样本对应进程被标记运行，或执行前状态变化 | 对应规则跳过，说明应用占用；不修改配置和数据库 |
| AC-07 失败与取消 | 锁定文件、拒绝访问文件和多条候选，执行中取消 | 不强删、不改ACL；逐项结果准确，取消后不启动后续操作；已完成项保留记录 |
| AC-08 日志失败 | 执行前或中途使日志不可写 | 未开始操作被阻止；已完成项不假定回滚，结果明确标识中断 |
| AC-09 重复准确性 | 同名不同内容、同大小不同内容及真实副本 | 只允许经过全内容复核的成员进入重复处置；全组选择被拒绝 |
| AC-10 保留副本变化 | 确认后移除保留副本，或选择包含保留副本的父目录 | 对应组或目录处置停止，保留约束不可由其他入口绕过 |
| AC-11 硬链接与ADS | 合成硬链接及默认数据相同但ADS不同文件 | 不虚报独立副本和可释放空间；无法确认完整语义时跳过 |
| AC-12 回收站范围 | 隔离测试卷有预览条目，确认后新增条目 | 只处置已确认对象；新增项和其他卷不变；永久处置单独确认 |
| AC-13 无隐式永久删除 | 让回收操作失败或位置不支持回收 | 显示失败，不自动转为永久删除 |
| AC-14 普通权限 | 普通用户遇系统或其他用户对象 | 跳过并显示权限不足；不弹隐式提权、不取得所有权 |
| AC-15 空与并发 | 零候选、取消扫描；执行时再次触发处置或改配置 | 执行禁用或要求完整预览；不会启动第二处置计划或扩大范围 |
| AC-16 原功能回归 | 合成目录执行空间分析、大文件和重复扫描 | 排行、逻辑合计、最大文件和重复组符合清单；原文件哈希不变 |

## 7．待确认或实测后定稿

- 是否安装最小Build Tools组件以解除本轮构建阻塞；见BUILD-BASELINE.md。
- 第一版最低支持系统、额外架构和便携配置保存位置；当前仅以本机x64为首轮验证对象。
- 首批软件版本、缓存目录、npm和pip缓存处置方式及年龄阈值须做版本样本核验；未核验规则不得启用。
- 普通模式关闭任意命令模板是统一保护所需的方案选择，尚未修改上游行为，需下一阶段范围评审确认。
- Shell回收站快照的逐项永久处置、权限语义和取消行为需要隔离虚拟磁盘验证；若平台不能满足，只能明确缩减处置范围，不能悄悄改为多卷清空。
- 日志保留期限和容量可先用简单上限，但数值待验证；不因日志轮换而删除用户文件或其他目录。
